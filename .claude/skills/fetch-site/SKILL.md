# 증빙 찾아오기 — 사이트 붙이기 (fetch-site)

청구 준비 줄의 **찾아오기**(`site-fetch/`, Help 서버 `POST /fetch`)가 `$ARGUMENTS` 의 가맹점 사이트에서 카드 거래 하나의 **필요 서류**를 찾아 첨부 파일로 넣게 만든다. 결과물은 셋이다.

| 결과물 | 어디에 | 누가 쓰나 |
| --- | --- | --- |
| 사이트 안내 | `site-fetch/sites/<영문 이름>.md` | 찾는 Claude 의 프롬프트에 붙음(`prompt.js guideFor` — 시작 주소의 도메인이 첫 줄 `hosts:` 에 맞을 때) |
| 기억한 찾는 방법(howto) 한 줄 | 마지막 답변의 `howto:` 줄 | 설정 페이지 채팅이 그 가맹점의 "기억한 찾는 방법" 칸에 넣음(`fetchSites[].howto`, 다음 찾아오기에 참고로 감) |
| 시험으로 받은 첨부 서류(PDF·이미지) | `site-fetch-out/<영문 이름>/` (git 제외) | 사용자가 확인 — 마지막 답변의 `files:` 줄 |

## 입력

가맹점 블록(설정 페이지의 만들기 프롬프트·채팅이 채워 보냄): 이름 · 카드 내역의 가맹점 글자 · 시작 주소 · 종류(강의/구독/기타)와 필요 서류 · 로그인해 둔 Chrome(`site.browser`) · 찾는 곳 메모 · 지난번에 찾은 방법 · 지난 결과 · 시험할 거래(사용일 · 금액). 그 뒤 `요청:` 한 줄이 있으면 그것이 이번에 할 일이다(예: "안내를 고쳐 줘", "견적서는 어디서 받는지 찾아 줘").
이름만 왔으면 `lib/fetch-sites.js KNOWN` 과 `site-fetch/sites/` 에서 찾고, 시험할 거래가 없으면 사이트 구매 내역의 가장 최근 결제로 시험한다. 빈 칸(＿＿)은 요청 글의 내용으로 채우고, 없으면 사이트에서 알아낸다.
가맹점 블록에 `- 개선점:` 줄(설정 페이지 가맹점 칸의 **개선점** — 사용자가 적은 안 되는 점·해야 할 것, [Help 에 개선 요청]으로 옴)이 있으면 그것이 이번에 고칠 것이다: 사이트 안내(절차 2)를 그에 맞게 고치고, 안내만으로 안 되는 것(새 저장 방식·화면 읽기·대체 서류 규칙)은 `site-fetch/` 의 손잡이(`cdp.mjs`)·규칙(`prompt.js` 의 `SYSTEM`·`DOC_HINT`)도 고친 뒤 `run.js` 로 확인한다. 끝나면 채팅이 그 칸을 비운다.

## 먼저 읽을 것

- `site-fetch/README.md` (구조 · 단독 실행 · 안전장치 · 실제 시험 표), `site-fetch/prompt.js` (찾는 Claude 에 주는 규칙 `SYSTEM` · 서류 설명 `DOC_HINT`), `site-fetch/sites/inflearn.md` · `azure.md` (사이트 안내 예)
- 이미 그 사이트의 안내가 있으면 그것과 지난 결과(`last` · 지난번에 찾은 방법)를 보고 **헤맨 곳만** 고친다.

## 절차

1. 요청 JSON 을 임시 폴더(스크래치, 없으면 `%TEMP%`)에 만들고 — 형식은 README "단독 실행"(`{ site: { label, url, kind, docs, hint, howto, browser }, tx: { shop, amount, usedDate } }`), 비밀번호는 파일에 넣지 않는다 — `node site-fetch/run.js 요청.json --out site-fetch-out/<영문 이름>` 으로 한 번 돌린다. 진행 줄 · 결과 JSON(`matched` · `howto` · `missing` · `cost` · `seconds`) · 받은 파일을 보고 어디서 헤맸는지 찾는다.
   - 로그인: `site.browser`(로그인해 둔 Chrome)나 서버 기본 브라우저(`site-fetch/local.json`)의 세션을 쓴다. 로그인이 필요한데 정보가 없으면(헤드리스 Help 서버에서는 아이디·비밀번호를 받지 않음) 작업 창이 남으니 "열린 Chrome 창에서 로그인한 뒤 다시 요청" 이라고 답하고 끝낸다. 대화형 Claude Code 에서 사용자가 직접 넣을 때만 환경 변수 `KRX_FETCH_ID` · `KRX_FETCH_PW`.
   - 시험은 한 거래로 두세 번까지. Opus 로 한 번에 보통 $0.1~0.8, 1~7분.
2. `site-fetch/sites/<영문 이름>.md` 를 만들거나 고친다. 첫 줄 `hosts: <사이트 도메인>, <로그인 도메인>`, 둘째 줄 `[이름] 출처: … (YYYY-MM-DD 실측)`, 그 아래 한 줄씩:
   로그인(칸 · 추가 인증) · 구매/결제 내역 주소와 행에서 날짜·금액·주문번호를 읽는 법 · 필요 서류마다 어디서 어떻게 저장하는지(`download` · `saveurl` · `pdf` · `capture`) · 함정(내려받기 지연, 다른 출처 iframe, 없는 주소 404, 해외 결제 금액 차이, 사이트가 주지 않는 서류).
   "사이트가 주지 않는다" 고 적기 전에 마이페이지의 탭·필터 칩 안쪽까지 보고, 목록이 늦게 그려지는(SPA) 화면은 `wait` 뒤 `look` 한다 — 2026-10-22 인프런 수강확인증(내 학습 › 수료증 탭의 필터)을 놓쳐 캡처로 대신했던 일.
3. 다시 `run.js` 로 돌려 필요 서류가 모두 나오는지(사이트가 주지 않는 것은 `missing` 이유와 함께) 확인하고, 결과·걸린 시간·비용을 `site-fetch/README.md` 의 실제 시험 표에 한 줄 더한다.
4. 필요 서류 이름이 `site-fetch/prompt.js` 의 `DOC_HINT` 에 없으면 한 줄 설명을 더한다(이 사이트에서 부르는 이름 — 예: Invoice · Receipt · 수강확인증).
5. `lib/fetch-sites.js` 의 `KNOWN` 에 `{ re, label, match, url, kind }` 를 더해 패널의 [자주 사용 등록]이 이 사이트로 미리 채워지게 하고 `node tests/prep-fetch.test.js` 를 돌린다.
6. `README.md` 의 증빙 찾아오기 절(사이트 안내가 있는 사이트 목록)에 이 사이트를 더한다.

## 지킬 것

- 확장에서 찾아오기를 시작하지 않는다(`KRX_PREP_FETCH.start` · `prepFetch` 메시지 · CDP 로 서비스워커 평가 모두). 확장 경로 확인은 사용자가 패널의 [찾아오기]를 누른다. 확장 설정(`help.url` 등)도 바꾸지 않는다.
- 사거나 바꾸지 않는다(조회 · 영수증 보기/내려받기만). 회사 시스템(`*.krs.co.kr` · `rcms.go.kr`)으로 가지 않는다. 아이디·비밀번호를 파일·로그·대화에 남기지 않는다.
- 다른 웹 사이트에 가는 코드는 `site-fetch/` 에만 둔다. 커밋하지 않는다 — 바뀐 파일과 시험 결과를 알려 주면 사용자가 확인하고 커밋한다.

## 마지막 답변 (설정 페이지 채팅이 읽는 형식)

첫 줄은 한국어 한 줄 요약(80자 이내, 머리표·마크다운 없이) — Help Chat 로그에 그대로 보인다. 그 다음 줄부터 한 줄씩:

```
howto: <이 사이트에서 빨리 찾는 방법 — 메뉴 경로 위주, 500자 이내 한 줄>
guide: site-fetch/sites/<영문 이름>.md
files: <받은 서류 파일 경로, 쉼표로> (없으면 "없음 — 이유")
missing: <못 찾은 서류와 이유> (없으면 생략)
```

그 뒤에 바뀐 파일 · 걸린 시간 · 비용 · 사용자가 할 일(로그인·추가 인증·저장 버튼)을 짧게.
