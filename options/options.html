설정

업무에 맞게 화면과 자동화 기능을 설정하세요.

내 참여 과제만 보기

사번이 참여인력과 맞으면 사번만 씁니다. 이름으로만 대조할 때 같은 이름이 둘 이상이면 과제를 표시하지 않고 위에 후보를 보여주니 본인 사번을 고르세요. 참여 여부는 과제별로 2시간 동안 기억하며(패널·팝업 ↻ 와 아래 진단은 다시 조회), 사번/이름이 바뀌면 다시 판정합니다. 본인 행의 참여기간이 오늘 이전에 끝난 과제는 현재 참여 과제로 보지 않습니다.

과제 선택

본인이 참여연구원 또는 과제책임자로 있는 과제만 나옵니다 ("내 참여 과제만 보기"가 켜진 경우). 체크를 바꾸면 바로 저장·적용되어 해제한 과제는 카드미청구 조회와 패널 표시, 아래 카드 목록에서 제외됩니다 (새로 생기는 과제는 기본 포함).

과제집행비율 비목 선택

체크한 비목만 과제집행비율 보기의 계산과 표에 들어가고, 체크를 풀면 계산과 표에서 모두 빠집니다. 체크를 바꾸면 바로 저장·적용됩니다. 목록은 위에서 선택한 과제의 자금현황(비목별 잔액)에서 조회된 비목이며, 아직 목록에 없는 비목은 이름에 인건비·연구수당·간접비가 들어가면 기본 제외, 그 외는 기본 포함입니다.

과제별 카드 귀속

기본 규칙: 과제카드발급내역의 카드 계좌번호가 그 과제 기본정보의 과제 계좌(지출계좌)와 같은 카드만 그 과제의 카드로 봅니다. 계좌가 다른 카드는 기본으로 빠지며, 아래 표에서 "포함"을 체크하면 그 과제에 넣습니다. 일치 카드의 체크를 풀면 뺍니다.

모니터링 카드 선택

귀속이 끝난 카드 중에서 패널에 보여줄 카드를 더 좁힙니다. "전체 보기"면 귀속된 모든 카드를 표시합니다.

목록에 없는 카드 뒷자리 직접 입력

아무것도 선택하지 않으면 전체 카드를 표시합니다. 패널에서는 카드번호 뒤 8자리(예: 0478-4126)로 표시됩니다.

카드 별명

패널의 카드별 보기와 거래 행에서 카드번호 뒤 8자리 대신 보여줄 이름입니다 (뒷자리는 툴팁과 옆 글씨로 남습니다). 입력하면 바로 저장·적용됩니다.

목록에 없는 카드 직접 입력

eClass 표시

표시를 끄면 저장 즉시 열려 있는 eClass 화면에서도 패널이 사라지고, 다시 켜거나 위치를 바꾼 뒤에는 eClass 홈을 새로고침하면 적용됩니다.

툴바 아이콘

기본은 툴바 아이콘을 누르면 바로 사이드 패널이 열립니다. 사이드 패널은 다른 탭으로 옮기거나 화면을 눌러도 닫히지 않고(닫기는 아이콘을 다시 누르거나 패널의 ×), 청구 준비 줄에 첨부 파일을 끌어다 놓을 수 있습니다. 팝업 창으로 바꿔도 팝업 제목 줄의 사이드 패널 버튼이나 아이콘 우클릭 메뉴의 "사이드 패널 열기"로 열 수 있습니다.

조회 옵션

청구서(카드) 입력 도우미

R&D ERP 청구서(카드) 화면에서 과제 지출내역을 골라 청구내역 폼이 뜨면, 예산(비목)과 RCMS 부가정보의 사용금액구분이 비어 있을 때 아래 기본값을 자동으로 채우고, "청구" 소제목 옆에 세목 빠른 선택 버튼을 넣으며, 첨부문서 칸에 파일을 끌어다 놓으면 첨부 처리를 합니다. 이미 고른 값은 바꾸지 않습니다. 변경 후 ERP 화면을 다시 열지 않아도 바로 적용됩니다.

청구 준비: 패널의 카드미청구 거래 행 밑 줄에서 위 목록의 청구종류를 고르고 첨부 파일을 끌어다 놓아 두면(이 브라우저에만 저장), 그 거래를 클릭해 청구서를 열 때 세목·청구종류를 고르고 파일을 첨부 목록에 올립니다. 청구서 작성 버튼은 청구서를 백그라운드 탭으로 열어 "내역 추가"까지 누릅니다 (결재요청은 하지 않음). 회의비·식사비·다과비(회의록이 필요한 청구종류)는 탭을 앞에 열어 증빙 [신규등록] 회의록 팝업을 띄우고(식비 여부·금액·참석자·RCMS 회의장소 자동 입력), 팝업을 저장하면 이어서 "내역 추가"를 누릅니다.

연구개발계획서 (연구내용 참조)

RND 폴더의 연구개발계획서 스냅샷 KR_<과제>.yaml(재생성본이 있으면 마지막 _rN)을 넣어 두면, 그 차년도의 개발목표·개발내용·성능목표·수행일정과 연구활동비 세부사용계획을 참조로 씁니다: 패널의 연구내용 탭(카드미청구 · 과제집행비율 다음)에서 과제별로 보이고, 청구 준비 자동 분류(LLM 설정 탭 — LLM 이 연결돼 있을 때)를 켜 두었으면 Claude 가 청구종류를 고를 때 그 과제의 계획을 근거로 보고, 비어 있는 청구내역(적요)을 쓸 때 개발내용·목표에서 용도를 고릅니다. 과제명으로 R&D ERP 과제에 저절로 잇고(이름이 조금 달라도 가장 비슷한 과제), 아래 표에서 바꿀 수 있습니다. 같은 과제·차년도에 다시 넣으면 바뀌고, 이미 넣은 판보다 오래된 판은 넣지 않습니다. history/*.yaml 이력 파일은 쓰지 않습니다. 이 브라우저(확장 저장소)에 남고, 공유 (Plus) 탭을 켜 두면 과제별 공유 파일로 같은 과제 사람들과 오갑니다(동료가 넣은 기록은 아래 표에 공유 표시 — 판·넣은 시각이 새로운 쪽이 남음).

급여·연구수당 (HR System)

패널의 급여·연구수당 보기를 누를 때(그리고 펼친 상태의 ↻) HR System(hr.krs.co.kr) 급여명세서 화면이 쓰는 API 로 올해 급여지급내역 목록과 각 달의 지급내역(소득명·금액), 직원 정보의 직급(P1~P4)을 백그라운드에서 읽어 저장합니다. 주기적으로 읽지는 않습니다(급여는 한 달에 한 번 바뀜). HR 탭을 열어 둘 필요는 없고 HR 에 로그인되어 있으면(세션이 살아 있으면) 됩니다. 세션이 끊기면 HR System 링크를 비활성 탭으로 열어 자동 로그인(SSO)한 뒤 다시 읽고, 그래도 안 되면 아래와 패널에 "로그인 필요"로 표시되며 열어 둔 탭에서 로그인한 뒤 ↻ 를 누르면 됩니다. 사번은 R&D ERP 사용자 정보(또는 아래 사번 설정)로 정합니다. 패널의 급여·연구수당 보기 버튼을 누르면 더 받을 수 있는 금액(월 기본연봉 × 12 × 직급 비율 − 올해 1월부터의 연구수당지급 합계 − 받기 예정)과 받기 예정 연구수당 목록만 표시하고, 기본연봉·올해 지급 합계·한도는 금액 칸의 툴팁에서 볼 수 있습니다. HR System 에는 아무것도 쓰지 않으며 값은 이 브라우저(확장 저장소)에만 남습니다.

공유 (Plus): 과제별 공유 폴더 (과제 정보 · 예산 · 참여연구원 · 연구내용 · 변경이력 · 예상 비용) 

    
과제마다 OneDrive(SharePoint) 폴더 하나 — 연차별 파일과 예상 비용 파일 — 를 두고 참여연구원과 맞춥니다. KRS WORKSPACE 에도 같은 폴더 주소를 주면 같은 파일로 동기화됩니다.

    
켜 두면 확장이 내 OneDrive 의 문서/업무/shared 밑에 과제마다 폴더(이름은 과제 약칭 → 없으면 Job Id → 없으면 과제번호)를 만들고, 그 안에 연차마다 n차년도.json 하나(과제 정보 · 사업비 예산 줄 · 참여연구원 참여율·지급액 계획 · 연구내용 기록 · 변경이력)와 예상비용.json 하나(모든 연차의 과제집행비율 예상 비용 — 연차에 걸치는 항목이 두 파일에 나뉘지 않게 따로)를 둡니다. 패널·팝업을 열 때와 항목을 바꾼 4초 뒤, 자동 갱신 때 저절로 맞춥니다.
      파일은 이 브라우저가 SharePoint(OneDrive)에 로그인돼 있는 것만으로 읽고 씁니다 — 서버·앱 등록·별도 로그인이 없습니다. 쓸 때는 SharePoint 탭을 잠깐(최소화된 창에) 열어 그 안에서 저장하고 닫습니다.
      과제 폴더는 과제 책임자(또는 그 과제의 자료를 먼저 넣은 사람)의 OneDrive 에 만들어지고, 자동 공유를 켜 두면 만들 때 R&D ERP 참여인력에게 편집 권한으로 공유됩니다. 참여연구원은 공유 (Plus) 만 켜 두면 됩니다 — 자동 찾기가 OneDrive 의 "나와 공유" 목록에서 내 참여 과제의 폴더를 찾아 맞춥니다(ⓘ 동료에게 공유하는 법). 폴더 이름은 보기 좋게 붙인 것일 뿐이고 과제는 파일 안의 과제번호로 알아보므로 이름을 바꿔도 됩니다. 팀 사이트 문서함의 폴더(https://krclass.sharepoint.com/sites/…/Shared Documents/…)를 밑폴더로 써도 됩니다.
      연차 파일의 변경이력은 덧붙이기만 하고(날짜 · 종류 · 항목 · 전/후 · 사유 · 누가 — WORKSPACE 쪽 항목도 함께), 예산 줄·참여연구원 계획·예상 비용은 수정 시각이 새로운 쪽이 남고 지운 것도 전파되며(90일), 연구내용 기록은 판·넣은 시각이 새로운 쪽, 과제 정보 가운데 R&D ERP 가 아는 칸(과제명·책임자·기간)은 ERP 값이 늘 이기고 Job Id·IO·메모는 WORKSPACE 몫입니다. 다른 사람이 같은 파일을 쓰는 중(체크아웃)이면 그 파일만 건너뛰고 다음에 다시 합니다. 켜기는 툴바 팝업 아래 줄에서도 됩니다.

청구 준비 자동화

      
첨부 서류를 읽고 청구종류와 청구내역 작성을 도와줍니다.

      

      
거래의 청구 준비 줄을 열 때, 파일(끌어다 놓기·화면 캡처·찾아온 서류)을 넣은 뒤, 청구내역을 고친 뒤 이 PC 의 Help 서버(POST /classify)가 빠른 모델(기본 claude-haiku-5-5, 서버 환경 변수 KRX_HELP_FAST_MODEL)로 한 번 묻습니다 — 보통 몇 초, 줄에 “Claude 분류 중…”이 보입니다.
        위 Claude API 에 키를 넣었으면 서버가 없거나 실패할 때(또는 늘) 같은 질문을 Claude API 로 직접 보내고, 결과 안내가 “Claude API: …”로 보입니다.
        가맹점·금액·사용일·과제명·청구내역·파일 이름과, 아직 종류를 안 정한 이미지·PDF 의 내용(이미지는 줄여서 — 영수증·캡처를 읽는 OCR 구실)이 Claude 로 갑니다. Claude 가 고른 값에는 점선 테두리와 AI 표시(툴팁에 이유)가 붙고, 직접 고른 값은 바꾸지 않습니다. 서버도 API 키도 없으면 아무 일도 하지 않습니다.

      
      
      
품목은 첨부 파일(찾아온 인보이스·거래명세서는 내용째, 2개까지)에서, 용도는 그 과제의 연구개발계획서(일반 설정 › 연구개발계획서 (연구내용 참조)에 넣은 KR_<과제>.yaml 이나 공유 (Plus) 로 받은 것)의 개발내용·목표에서 골라 씁니다(예: “Azure 클라우드 사용료(2026년 9월분) - 차단기 제어 알고리즘 시뮬레이션용”).
        청구종류를 바꾸거나 서류가 새로 들어오면 다시 쓰고, 직접 고친 글은 바꾸지 않습니다(지우면 다시 씀). 계획서가 없는 과제는 과제명으로 씁니다. 서버를 0.8.5 개발 중에 띄웠다면 다시 실행해야 합니다.
