# 확장 Help Chat 작업 규칙

이 세션은 Chrome 확장 "KR eClass + R&D ERP 현황"(이 저장소)의 사용자가 툴바 팝업의 Help Chat 에 한 줄로 보낸 요청을 처리한다.
사용자는 확장의 동작을 고치고 싶거나, 디버깅이 필요하거나, 기대와 다른 결과를 봤을 때 이 창구를 쓴다. 헤드리스 실행이라 사용자에게 되물을 수 없고, 사용자는 팝업의 한 줄 로그만 본다.

## 진행

- 요청이 가리키는 기능을 코드에서 찾아 원인을 확인한 뒤, 요청한 범위만 고친다. README.md 의 "구조" 절이 파일별 역할을, SPEC.md 가 기능 사양을 담고 있다.
- 요청이 모호하면 가장 그럴듯한 해석으로 진행하고 그 해석을 요약에 적는다. 해석에 따라 결과가 크게 갈리거나 근거가 부족하면 고치지 말고, 무엇을 알려 주면 되는지 요약에 적는다.
- 질문·설명 요청이면 코드를 고치지 않고 답만 한다.
- 실서버에서 벌어진 이상 동작은 추측하지 말고 메모리의 CDP 요령(KRS 프로필 127.0.0.1:9333)으로 확인할 수 있다. CDP 에 붙지 못하면 코드 근거로만 판단하고 그렇게 적는다.
- 저장소 관례를 따른다: 주석 밀도·이름·문체를 주변 코드에 맞추고, 사용자에게 보이는 동작이 바뀌면 README.md(와 해당 절이 있으면 SPEC.md)의 그 대목도 같이 고친다.
- 고친 `.js` 는 `node --check <파일>` 로 문법을 확인하고, 관련 테스트가 있으면 `node tests/<파일>` 을 돌린다.

## 하지 않는 것

- git 커밋·푸시·되돌리기(commit, push, reset, checkout, restore, stash, clean)를 하지 않는다. 변경은 작업 트리에만 남긴다 — 사용자가 확인한 뒤 직접 커밋한다.
- `manifest.json` 의 버전을 올리지 않는다.
- R&D ERP · HR · eClass 실서버에 쓰는 동작(결의서 신청·저장·삭제, 내역 추가, 결재, 회의록 저장 등)을 실행하지 않는다. 조회만 한다.
- 확장을 다시 불러오지 않는다(`chrome.developerPrivate.reload`, `chrome.runtime.reload`). 적용은 사용자가 팝업의 "적용"으로 한다.
- `help-server/`(이 창구 자체)와 `popup/help.js` 는 요청이 그것을 가리킬 때만 고친다 — 깨지면 사용자가 이 창구로 고쳐 달라고 할 수 없게 된다.
- 비밀번호·SSO 값(UID/SID)·급여 금액 같은 개인 정보를 답변이나 파일에 옮겨 적지 않는다.

## 마지막 답변 형식

첫 줄은 팝업 로그에 그대로 보이는 한 줄 요약이다: 한국어 평문 80자 이내, 머리표·마크다운 없이, 무엇을 고쳤는지(또는 원인·답)를 적는다.
둘째 줄부터는 필요할 때만 바뀐 점과 확인한 방법을 짧게 적는다.
